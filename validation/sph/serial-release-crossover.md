# P1-07 Serial SPH Release 精简前后配对复测

本页保留一维固定 CSR 的历史配对实验。现行构建由一维测试与显式 benchmark 共用验证夹具。[现行夹具源码](fixed_csr/) · [Serial 验证](serial.md)

## 测量方法

主实验于 `2026-11-19T11:46:43+08:00` 至 `2026-11-19T11:51:06+08:00` 在同一台 Apple M2 Pro arm64（8P+4E，16 GB）上执行。系统为 macOS 27.2.1（26B131），编译器为 AppleClang 21.0.0.21000401，两版均使用 Release `-O3 -DNDEBUG` 和同一套 Kokkos 5.2.2 Serial 安装。开始与结束均接通电源。系统接口未返回温度或性能状态，未记录 CPU 频率。结果限于此单机、工具链和工作负载。 [Serial 验证环境](serial.md#历史离线执行) · [实验元数据](../../results/p1-07-release-crossover-20261119T114553/primary/meta.json)

直接运行原有四个二进制，实验前后核对 SHA-256。每种精度先各预热一次 A 和 B 进程，再按随机次序执行 16 个配对块，其中 ABBA 和 BAAB 各 8 个。每块依次启动四个独立进程。每个进程保留原有的小例和默认大例流程，每例先预热一次，再热测三次，另执行一次独立 Kokkos Tools 计量。主指标为大例热端到端耗时，范围从输入构造到重排后第二个 accepted 快照可读。每进程先取三次热测中位数，每块计算 B、A 各自两个进程的对数均值之差。块间取均值后变换为百分比，并以 16 个块为单位计算双侧 95% t 区间。各阶段毫秒差改用进程内热测算术均值，以便相加。清理独立计时，表内各阶段点估计可相加，区间按各指标分别计算。 [预定设计](../../results/p1-07-release-crossover-20261119T114553/primary-design.json) · [原始观测](../../results/p1-07-release-crossover-20261119T114553/primary/observations.jsonl) · [分析脚本](../../results/p1-07-release-crossover-20261119T114553/analyze.py)

## 密度窗口归因

在 B 的同一 Release 构建上分别改变归约趟数和 M₄ 外段的两个提前返回条件，组成四种组合。每种精度做 12 个完整的顺序平衡块，时间为 `2026-11-19T11:51:42+08:00` 至 `2026-11-19T11:56:58+08:00`。下表给出首次窗口耗时的配对变化。重排后窗口的方向全部一致。[实验设计](../../results/p1-07-release-crossover-20261119T114553/attribution-design.json) · [配对数据](../../results/p1-07-release-crossover-20261119T114553/attribution/analysis.json) · [保留提前返回时拆开归约的对照](../../results/p1-07-release-crossover-20261119T114553/attribution/guarded-split-analysis.json)

| 单因素变化 | float（95% CI） | double（95% CI） |
| --- | ---: | ---: |
| B 中拆开 gather 与普通 double 求和 | +10.24% [8.82%, 11.68%] | +16.21% [13.70%, 18.77%] |
| 恢复两个提前返回，仍采用单次遍历 | −32.39% [−33.98%, −30.77%] | +11.39% [9.31%, 13.50%] |
| 在已恢复两个提前返回的版本上拆开遍历 | +16.03% [13.75%, 18.36%] | +15.64% [14.19%, 17.11%] |

AppleClang 为 B 的 float 生成了同时计算内外两段、最后用 `fcsel` 选值的指令。即使将归约拆开，仍会计算两段。double 和精简前的 float 都会跳过未选中的多项式。该输入有 2,099,200 条边满足内段条件 `q <= 1`，占 53.3%。[汇编片段与对象摘要](../../results/p1-07-release-crossover-20261119T114553/m4-disassembly.txt)

从 `2026-11-19T11:57:35+08:00` 至 `2026-11-19T12:00:26+08:00`，每种精度又做了 6 个顺序平衡块。仅在已有的内段条件上标记 `[[likely]]`，该工具链便为两种精度均生成条件跳转。相对 B，float 首次和重排后窗口分别缩短 40.50% [37.38%, 43.47%] 和 43.11% [40.90%, 45.23%]。double 对应变化为 −1.09% [−2.45%, 0.28%] 和 +3.73% [−3.89%, 11.95%]。单独恢复零核尾或域外返回也能改变 float 指令，但两者都增加了 double 的窗口耗时。采用分支提示，保留一次归约、补偿减法和质量优先的乘法顺序。[候选对照](../../results/p1-07-release-crossover-20261119T114553/lowering/analysis.json)

## 初始化与重排归因

从 `2026-11-19T12:00:37+08:00` 至 `2026-11-19T12:03:03+08:00`，每种精度做了 8 个顺序平衡块。两版重排探针使用各自原有的库、头文件及基准源码，头文件和基准源码在加探针前均与各自清单匹配。只在计时副本中细分阶段。下表为进程热样本算术均值的块配对差，方向为 B 减 A。[探针设计](../../results/p1-07-release-crossover-20261119T114553/probes-design.json) · [探针数据](../../results/p1-07-release-crossover-20261119T114553/probes/probe-analysis.json)

| 重排内的工作 | float 差值 ms（95% CI） | double 差值 ms（95% CI） |
| --- | ---: | ---: |
| 从快照读取 ID 并构造两个向量 | +5.34 [5.15, 5.54] | +5.36 [5.14, 5.58] |
| 反转行、旋转列 | −0.05 [−0.09, −0.01] | −0.03 [−0.07, 0.01] |
| `Participant::reorder` 迁移 | −1.82 [−4.27, 0.64] | +1.41 [−2.67, 5.50] |
| 取新快照并释放旧快照 | −0.0013 [−0.0023, −0.0002] | +0.0003 [−0.0003, 0.0008] |

旧版从连续 ID 区间构造向量，精简版循环逐个读取 2,887,682 个 ID。保持同一向量循环和标量接口，只内联 `Snapshot::row_id/column_id`，两种精度构造向量都从约 5.8 ms 降至约 3.3 ms。按热样本均值，float 节省 2.62 ms [2.49, 2.74]，double 节省 2.66 ms [2.52, 2.80]。修正版采用这一改动。跨窗口读取仍由完整快照持有布局与读授权。[标量读取对照](../../results/p1-07-release-crossover-20261119T114553/lowering/probe-analysis.json)

在精简版中只改变完整支持域谓词的内联位置，同样的计时探针包围实际 CSR 逐边校验循环。各进程热中位数的几何均值，float 从 49.75 ms 降至 48.15 ms（−3.22%，95% CI −4.67% 至 −1.75%），double 从 49.68 ms 降至 47.68 ms（−4.04%，−5.18% 至 −2.89%）。按热样本算术均值，逐边循环的配对差值为 float −1.18 ms [−2.64, 0.27]、double −2.38 ms [−2.97, −1.78]。整个初始化阶段的两个区间均跨过零。修正版把同一谓词和减法余项放在内部方法头文件，供校验和核函数共用。[逐边探针数据](../../results/p1-07-release-crossover-20261119T114553/probes/probe-analysis.json)

## 三项夹具优化的复验

M₄ 分支提示、完整支持域判断内联和两个标量 ID 读取内联组成版本 D，源码输入清单 SHA-256 为 `a63743b1057679af812b3fb43c866774048513155dd5024ebd545c579a0198cc`。从 `2026-11-19T12:03:46+08:00` 至 `2026-11-19T12:04:42+08:00` 完成干净的四组 Serial 构建。Debug/Release × float/double 分别通过 21/21 项 CTest，均无跳过，各配置的搬迁包测试均执行并通过 3 个消费者。[源码清单](../../results/p1-07-release-crossover-20261119T114553/fixed-source-sha256.txt) · [验证日志](../../results/p1-07-release-crossover-20261119T114553/validation/)

从 `2026-11-19T12:04:45+08:00` 至 `2026-11-19T12:08:30+08:00`，每种精度将 A、B、D 的六种执行顺序各使用三次，共 18 个配对块。各版使用原基准的计时边界，数值与 Kokkos 计数仍一致。[相对 A 的结果](../../results/p1-07-release-crossover-20261119T114553/confirm/vs-original.json) · [相对 B 的结果](../../results/p1-07-release-crossover-20261119T114553/confirm/vs-simplified.json)

| 精度 | D 相对精简前 A（95% CI） | D 相对精简后 B（95% CI） |
| --- | ---: | ---: |
| float | −0.76% [−1.54%, +0.04%] | −3.27% [−4.03%, −2.50%] |
| double | +1.40% [+0.43%, +2.38%] | −0.32% [−1.28%, +0.64%] |

double 的两个密度窗口已经比精简前分别快 23.82% 和 23.38%，初始化和重排分别慢 2.26% 和 3.07%。据此继续对照这两个阶段。

## 最终大例

从 `2026-11-19T12:10:04+08:00` 至 `2026-11-19T12:15:12+08:00`，每种精度再做 12 个六版本顺序平衡块。A、D 和最终版 V 用原计时边界，另三个配套副本细分初始化和重排。V 在 D 上由基准调用方按已知行列数设置目标 ID 向量大小，再按索引赋值，涉及四行代码。仍从同一完整快照读取全部 ID，在相同的重排计时段内生成两组排列。单独测得这一步 float 从 3.26 ms 降至 0.73 ms，double 从 3.32 ms 降至 0.71 ms。相对精简前的连续区间复制，两种精度最终只多用约 0.2–0.3 ms。这个收益属于调用方准备排列。[ID 构造代码](../../benchmarks/sph/sph_benchmark.cpp) · [分段计时](../../results/p1-07-release-crossover-20261119T114553/residual/probe-analysis.json)

| --- | ---: | ---: | ---: | ---: | ---: |

最终端到端区间均包含零，且排除了最初观察到的 +5.34% 和 +2.18%。个别阶段仍有可测差异。无细分探针的 float 重排比 A 慢 2.43% [0.87%, 4.00%]，double 初始化比 A 慢 2.22% [1.01%, 3.45%]。在带细分探针的对照中，double 的 ID/CSR 构造、整个邻域校验和整段初始化差值区间均跨过零，无法把这 2.22% 稳定归到某个初始化子步骤。两种精度最终版的 owned 和、逐 ID 判据及 Kokkos 分配、复制与 fence 计数均通过复核。此组样本支持保留单遍 CSR、普通 double 归约和完整 Snapshot 的读取约束。[最终版与精简前](../../results/p1-07-release-crossover-20261119T114553/residual/vs-A.json) · [向量填充单因素对照](../../results/p1-07-release-crossover-20261119T114553/residual/vs-D.json)
